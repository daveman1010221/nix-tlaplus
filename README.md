# nix-tlaplus

The [TLA+ tools](https://github.com/tlaplus/tlaplus) (TLC, SANY, PlusCal) built with Nix from their source at a pinned
commit, so that a model check is run by the same checker everywhere.

## What it builds

| | |
|---|---|
| TLA+ tools | commit `d8fb231` of the 1.8.0 pre-release (2026-11-06), pinned by hash (`release.nix`); upstream's `v1.8.0` tag moves with each nightly |
| Java | JDK 21 (headless), nixpkgs'; the code is compiled for Java 11, as upstream's build sets |
| Ant | nixpkgs' |

The tools are built as upstream's Ant build builds them (`tlatools/org.lamport.tlatools/customBuild.xml`, targets
`generate compile dist`):
- the TLA+ parser is generated by JavaCC;
- the tools are compiled;
- their runtime libraries are unpacked into `tla2tools.jar`. These are javax.mail, JLine, Gson, LSP4J and prettier4j,
  which upstream keeps as jars in its repository.

What upstream's build reads from a checkout and a clock is given instead:
- **The manifest's git fields:** branch, tag, revision, and commit count. TLC prints the short revision with its version.
- **The timestamp:** the commit's time. TLC's version number is that timestamp
  (`Version 2026.11.06.220854 (rev: d8fb231)`).
- **The build tag:** the nightly's tag at that commit.

The jar is normalized, so the build is reproducible (`nix build --rebuild` finds no difference).

The Community Modules are not included. The manifest still names `CommunityModules.jar` on its class path, but TLC
runs without it.

## Use

```sh
nix build .#tlaplus                      # ./result/bin/{tlc,sany,pcal}, ./result/share/java/tla2tools.jar
nix shell .#tlaplus -c tlc -config Model.cfg Spec.tla
nix flake check                          # a model that holds; a safety and a liveness violation refused
```

`tlc`, `sany` and `pcal` run `tlc2.TLC`, `tla2sany.SANY` and `pcal.trans` on that JDK, with the parallel garbage
collector TLC recommends. Pass `-Xmx` through `JAVA_TOOL_OPTIONS` to bound the heap.

## Checks

`tests/` holds one specification, a counter that counts to a bound, checked three ways. TLC's exit status is compared
with `tlc2.output.EC.ExitStatus`:
- with weak fairness, it holds its invariant and reaches its bound (0);
- an invariant some state breaks is a safety violation (12);
- without fairness, the counter may stop, so "it reaches its bound" is a liveness violation (13).
